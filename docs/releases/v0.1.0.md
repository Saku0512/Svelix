# Svelix v0.1.0

> Draft GitHub Release notes. Preparing or merging this document does not authorize a Git tag, npm publication, or GitHub Release.

Svelix v0.1.0 is the first release of a small, composable, native-first UI library for Svelte 5. It uses ordinary Svelte components and the standard toolchain; no custom compiler, preprocessor, CSS framework, or runtime dependency is required.

## Install

After the package is published with maintainer approval:

```sh
npm install svelix
```

```svelte
<script lang="ts">
  import { Button } from 'svelix';
  import 'svelix/styles.css';
</script>

<Button>Continue</Button>
```

## Included components

- `Button`: native button semantics with primary, secondary, outline, and ghost variants.
- `Input`: native input types with value, checked, file, radio-group, and checkbox-group bindings.
- `Checkbox`: controlled or uncontrolled native checkbox state plus `indeterminate` binding.
- `RadioGroup` and `Radio`: native fieldset, legend, radio naming, selection, keyboard behavior, and form participation.
- `Label`: explicit or wrapping native labels without hidden ID generation.
- `Separator`: semantic or decorative horizontal and vertical separators.

All components forward their applicable native attributes and event callbacks. Import `svelix/styles.css` once to provide the shared theme tokens.

## Theme and customization

- Light tokens are the default.
- Add `data-svelix-theme="dark"` or `data-svelix-theme="light"` to select a theme for a subtree.
- Override `--svelix-*` custom properties at the application, theme-scope, or component level.
- Svelix does not add a page reset, font, page background, browser color scheme, validation messages, or submission logic.

## Accessibility

The components use native buttons, inputs, labels, fieldsets, legends, and separators. Automated Chrome checks cover semantic roles, accessible names and descriptions, exposed states, keyboard interaction, visible focus, forced-colors borders, and post-hydration behavior.

Automated results do not establish full WCAG conformance. Real screen-reader testing, Firefox and Safari/WebKit coverage, OS contrast-theme checks, zoom/reflow, text spacing, and application-level labels and error messages remain consumer or release validation work.

## Compatibility

- Svelte: 5.59.0 or newer within the Svelte 5 release line; 5.59.0 is exercised in a clean packed consumer.
- Build integration: standard Svelte 5 plus Vite/`@sveltejs/package`; SvelteKit is not required.
- SSR: server rendering and in-place hydration are verified.
- Browser automation: Google Chrome 158 on Linux.
- Development and release checks: Node.js 24.18.0 and npm 12.0.1.

Firefox, Safari/WebKit, mobile browsers, and real assistive technologies are not claimed as automated v0.1.0 coverage.
